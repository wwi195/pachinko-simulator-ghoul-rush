# RUSH中の「アツさ」だけを抽出したパチンコシミュレーターを作った話

パチンコの魅力って、正直言うと「通常時にハンドルを握っている時間」より、「RUSHに入ってから、保留を見つめて連チャンを期待している時間」に集約されている気がする。

そこで今回、東京喰種のパチンコ機をベースに、**通常時を全部すっ飛ばしてRUSH中の演出だけを繰り返し楽しめるシミュレーター**を作った。

- プレイ: https://wwi195.github.io/pachinko-simulator-ghoul-rush/
- コード: https://github.com/wwi195/pachinko-simulator-ghoul-rush

## コンセプト：通常時はワンクリックで終わらせる

スタートボタンを押すと、通常時の当選までの過程（何千回転も回す作業）は裏側で一瞬にシミュレートされ、「投資額◯◯円（◯◯回転）」という結果だけが表示される。

そこから先は、RUSH中の保留・先読み・演出モードといった「魅せる」要素に全振りしている。手打ちも放置観戦もしない、RUSH部分だけの純粋抽出版。

## 保留の色とテンパイ数字、両方に「信頼度」を持たせた

保留（先読み）の色は無色・点滅・青・緑・赤・虹の6段階。それぞれに「この色が出たとき実際に当たっている確率」を個別に設定できる仕組みにしてある。

さらに今回、保留の色だけでなく**リーチ中に止まるテンパイ数字（1〜8）にも同じ考え方を導入した**。7が出たら信頼度100%、3は90%、残りの6数字は均等——という具合に、数字ごとに「当たりやすさの体感」を作り込める。

面白かったのは、これを実装する過程で「当選率そのものは一切変えずに、数字の見た目の信頼度だけを操作する」という要件が出てきたこと。実機の大当たり確率（1/95.3）は`logic.js`側でそのまま保持しつつ、「リーチの両端に表示する数字をどれにするか」という**見せ方の抽選だけ**を保留色と同じ重み付けの仕組みで独立させることで解決した。当落を決める抽選と、それをどう魅せるかの抽選を完全に分離する——という設計判断は、今回の開発で一番腑に落ちた部分だった。

## 演出モードは4種類、しかもRUSH中に切り替え可能

- **デフォルト**：素の当選告知
- **突撃**：当たり保留が先頭に来た瞬間、一瞬だけ先バレ画像が差し込まれる（裏では通常のリーチ演出がそのまま進行）
- **リゼ襲来**：当たり保留がキューに積まれた瞬間、専用画像が画面いっぱいに表示される
- **月山絶叫**：リーチ中に予告ボタンが出現し、押すと色が光る。当たりなら必ずレインボー＋「僕のだぞ！」の文言に変化する

演出モードはRUSH開始前だけでなく、**RUSH中にも切り替えられる**ようにした。ただし「モードを変えた瞬間に、キューの中で待機中の保留の演出まで変わってしまう」のはおかしい。なので、保留を生成した時点のモードをその保留自身に記録しておき、消化時はその保留が生まれた時点のモードで演出する、という設計にしてある。

## 保留の補充とリーチ演出を、完全に独立したタイマーにした

地味に一番効いた変更がこれ。最初は「保留を1個消化したら、その後に次の保留を補充する」という素直な作りだったが、これだとリーチ演出（最大3秒程度）の間、補充が止まってしまう。

実機の感覚に近づけるため、保留の補充ループと、保留の消化（リーチ〜当落判定）ループを完全に別のタイマーに分離した。結果、リーチ中でも裏で保留がどんどん貯まっていく、という体感になった。

## 数字だけで会話しながら作った感覚

このプロジェクトは、「保留色の発生率を80%にして」「テンパイ数字ごとに信頼度を持たせられる？」「当選確率は変えずに」というような、かなり具体的なパラメータ調整の会話を積み重ねながら作った。

途中、「7で必ず当たる」という仕様を一度実装してから、「それだと実機の大当たり確率がズレる」と気づいて撤回し、「当落は変えずに見た目の信頼度だけ変える」方式に作り直す、という手戻りもあった。遠回りだったけれど、結果的に「抽選ロジック」と「演出」をきれいに分離するという、後から見ると一番良い設計にたどり着けた気がする。

作ったものを実際に触りながら、少しずつ確率やタイミングの数字を詰めていく——プログラミング未経験でも、会話ベースでここまで作り込めるのは面白い体験だった。
